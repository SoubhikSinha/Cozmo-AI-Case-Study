# Reproduction Bundle

Everything needed to regenerate every reported number from raw inputs.

## What's cached vs. live

**Nothing is cached.** Every number in `docs/` (gates, timing, device matrix, head-to-head) is computed live from the raw captures in `media/` on each run — there is no external model call anywhere in this pipeline (damage detection is heuristic CV: HSV thresholds + edge detection, not a VLM/API call), so there's no cache-vs-live distinction to manage. This means the walk-in test's live-run requirement is automatically satisfied: the reproduction bundle *is* the live path, not a replay of a cache.

## One command

```bash
.venv/bin/python3 scripts/reproduce_all.py
```

Runs, in order:
1. `scripts/run_benchmark.py` — reconstructs `bedroom_1` from raw LiDAR/photo/video captures in `media/`, scores every Part 2 gate against `media/ground_truth/bedroom_1/ground_truth.json`, times each reconstruction, writes `docs/benchmark_report.md`, `docs/benchmark_results.json`, `docs/timing.md`.
2. `scripts/generate_device_matrix.py` — reads the just-written `docs/benchmark_results.json`, writes `docs/device_matrix.md`.
3. `scripts/run_head_to_head.py` — reconstructs `bedroom_1` again (LiDAR tier), parses the real magicplan PDF export (already transcribed to `media/competitor_benchmark/magicplan/measurements.json`), compares both against ground truth, writes `docs/head_to_head_table.md`/`.csv` and `docs/head_to_head_report.md`.

Then, separately:

```bash
.venv/bin/python3 -m pytest tests/ -q
```
confirms the 77 unit/integration tests (including the fixed damage-detection bounds, confidence-interval ordering, and stitching correctness that the reported numbers depend on).

## Raw inputs this reads

- `media/lidar/bedroom_1/<timestamp>/` — 3D Scanner App "All Data" export (per-frame pose/depth/intrinsics + images)
- `media/photos/bedroom_1/`, `media/photos/bedroom_1_recapture/` — native Camera stills
- `media/video/bedroom_1/*.MOV` — native Camera walkthrough
- `media/ground_truth/bedroom_1/ground_truth.json` — laser/tape measurements
- `media/competitor_benchmark/magicplan/measurements.json` — transcribed from the real magicplan PDF export (`media/competitor_benchmark/magicplan/Bedroom + Drawing Space Report.pdf`)

## Fix-loop before/after (separate, since it spans a code change)

`results/fix_loop/before/` and `results/fix_loop/after/` are regenerated by the commands in their respective `command.txt` files (checked-out at the commit *before* the fix, and with the fix applied, respectively) — verified byte-identical from a clean `git clone` (see `docs/fix_loop_report.md`).

## What this does NOT regenerate

The `results/fix_loop/before/` snapshot specifically requires checking out the pre-fix commit (`git log` in this repo) to reproduce exactly — running `scripts/run_benchmark.py` on current `HEAD` reproduces the **after** numbers, not the historical **before** ones, since the fix is already applied on `HEAD`. This is expected and documented in `results/fix_loop/before/command.txt`.
